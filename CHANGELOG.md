## [0.1.0] - 2026-10-22

The first release: a Rust port of [Linz](https://github.com/apskhem/linz) on top of axum.

### Added

- `Endpoint` builder for declaring operations: query, header, path, cookie and body types,
  responses, tags, security and docs metadata.
- `Api` route builder with `get`/`post`/`put`/`patch`/`delete`, `nest`, `merge` and `config`.
  Linz-style `LinzEndpointGroup`s with `merge_endpoint_groups` and `apply_group_config` are
  supported too.
- Request validation against JSON Schema 2020-12 schemas generated by schemars 1.x, including
  format validation, with schema-guided coercion of textual inputs. Failures respond `400` with
  JSON:API errors.
- Compile-time checked response types (`.returns(..)`) and runtime validation of responses.
- Request and response bodies: JSON, `multipart/form-data` (with `File`),
  `application/x-www-form-urlencoded`, `application/octet-stream`, text and HTML, and
  streamed responses.
- Router state for handlers (`Context::state`).
- Security schemes (HTTP, API key, OAuth2, OpenID Connect, mutual TLS) with token extraction,
  scopes and typed access to their results (`Context::extension`).
- OpenAPI 3.1 document generation (`build_json`), served by `create_api` with Scalar, Swagger UI,
  Redoc, RapiDoc or Stoplight Elements.
- `create_api` options for CORS, logging, a fallback handler and a request body limit
  (2 MiB by default).
- Registration checks reported as `LinzError`: invalid routes, duplicate routes or operation
  IDs, and path parameters that do not match the path type.

### Differences from Linz

- Multiple securities on an endpoint are documented as a single requirement object, matching
  the runtime behavior where all of them are required.
- Repeated query, form and cookie keys keep their last value; there is no multi-value mode.
- When a handler sets no status, the status passed to `.returns(..)` is used.
