# linz-rs

A Rust port of [Linz](https://github.com/apskhem/linz): a web framework on top of
[axum](https://github.com/tokio-rs/axum) with first-class OpenAPI documentation support.

## Usage

```rust
use axum::Router;
use linz_rs::*;
use schemars::JsonSchema;
use serde::{Deserialize, Serialize};

#[derive(Deserialize, JsonSchema)]
struct UserPath {
    user_id: u32,
}

#[derive(Serialize, JsonSchema)]
struct User {
    id: u32,
}

let endpoints: LinzEndpointGroup = vec![(
    "get:/users/:user_id".into(),
    Endpoint::new("getUser")
        .path::<UserPath>()
        .response(200, JsonBody::new::<User>())
        .response(404, true)
        .handler(|req, _ctx| async move { Ok(User { id: req.params.user_id }.into()) }),
)];

let spec = build_json(&BuilderConfig::new(info, &endpoints))?;
let app = create_api(Router::new(), endpoints, CreateApiConfig {
    docs: Some(DocsConfig {
        viewer: DocsViewer::Scalar,
        spec,
        docs_path: "/docs".into(),
        spec_path: "/openapi.json".into(),
        theme: None,
    }),
    ..Default::default()
})?;
```

See `examples/bootstrap.rs` for a complete example (`cargo run --example bootstrap`).

## Behavior

- Request parts (body, queries, params, headers, cookies) are validated against the JSON
  schemas generated by `schemars`; failures respond `400` with JSON:API errors whose `meta`
  is `{ "in": <part>, "result": [...] }`. Textual inputs (query, path, header, cookie, form
  data) are coerced to numbers/booleans when the schema requires it.
- Responses are validated against the schema declared for their status (or the default
  response); undeclared statuses and invalid payloads respond `500`.
- Without an explicit status, `post` endpoints respond `201` and others `200`.
- Errors returned as `ApiError` are rendered as `{ "errors": [...] }` with their status.
- Unmatched requests respond `404` (`Cannot find <METHOD> <path>`), after an optional
  fallback handler.

## Limitations

Content Type Supports
  - `application/json`
  - `application/octet-stream` (as `File`)
  - `application/x-www-form-urlencoded`
  - `multipart/form-data` (files as `File`)
  - `text/plain` and `text/html` (responses)

Multiple values of query strings, url-encoded and multipart bodies are only kept when
enabled by `RequestConfig`; otherwise the last value is used.
