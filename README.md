# linz-rs

A Rust port of [Linz](https://github.com/apskhem/linz): a web framework on top of
[axum](https://github.com/tokio-rs/axum) with first-class OpenAPI documentation support.

## Usage

```rust
use axum::Router;
use linz_rs::*;
use schemars::JsonSchema;
use serde::{Deserialize, Serialize};

#[derive(Deserialize, JsonSchema)]
struct UserPath {
    user_id: u32,
}

#[derive(Serialize, JsonSchema)]
struct User {
    id: u32,
}

let api = Api::new()
    .get(
        "/users/:user_id",
        Endpoint::new("getUser")
            .path::<UserPath>()
            .returns(200, JsonBody::new::<User>()) // the handler must return a `User`
            .response(404, true),
        |req, _ctx| async move { Ok(User { id: req.params.user_id }) },
    )
    .config(GroupConfig::new().tag("Users"));

let app = create_api(Router::new(), Api::new().nest("/v1", api), CreateApiConfig {
    docs: Some(DocsConfig {
        viewer: DocsViewer::Scalar,
        spec: BuilderConfig::new("My API", "1.0.0"), // built from the endpoints
        docs_path: "/docs".into(),
        spec_path: "/openapi.json".into(),
        theme: None,
    }),
    ..Default::default()
})?;
```

See `examples/bootstrap.rs` for a complete example (`cargo run --example bootstrap`).

## Behavior

- Request parts (body, queries, params, headers, cookies) are validated against the JSON
  schemas generated by `schemars`; failures respond `400` with JSON:API errors whose `meta`
  is `{ "in": <part>, "result": [...] }`. Textual inputs (query, path, header, cookie, form
  data) are coerced to numbers/booleans when the schema requires it.
- The handler's response type is set by `.returns(status, body)` and checked at compile
  time. Responses are also validated against the schema declared for their status (or the
  default response) at runtime; undeclared statuses and constraint violations respond `500`.
- Handlers can read the router state (`Router::with_state`) through `Context::state`.
- Registration fails early (`LinzError`) on invalid keys, duplicate routes or operation IDs,
  and path parameters that do not match the path type.
- Request bodies are limited to 2 MiB by default (`413` beyond).
- Without an explicit status, `post` endpoints respond `201` and others `200`.
- Errors returned as `ApiError` are rendered as `{ "errors": [...] }` with their status.
- Unmatched requests respond `404` (`Cannot find <METHOD> <path>`), after an optional
  fallback handler.

## Limitations

Content Type Supports
  - `application/json`
  - `application/octet-stream` (as `File`)
  - `application/x-www-form-urlencoded`
  - `multipart/form-data` (files as `File`)
  - `text/plain` and `text/html` (responses)

When a query string, url-encoded or multipart field repeats, the last occurrence is used.
